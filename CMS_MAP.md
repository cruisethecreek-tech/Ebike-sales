# CMS Map — which Google Sheet tab feeds what

This is the reference for the "I changed it in the code but the website didn't
change" problem. Most of the site's text, links, images, and prices are driven
by a **Google Sheet** (through a Google Apps Script web app), not by the files in
this repo. This doc says exactly which tab controls what.

---

## The one rule to remember

> **The Google Sheet is the live source of truth. The values in the repo are only
> fallbacks that show for a split second (or if the Sheet is unreachable).**

So if a price, link, headline, or photo is wrong on the live site:
- **Fix it in the Sheet, not the code.** Editing the HTML usually does nothing on
  production, because the Sheet value overrides it a moment after the page loads.
- The map below tells you **which tab and which key** to edit.

There are two exceptions that ARE controlled by the repo (not the Sheet):
- **Jetti walking-pole prices** → `pricing-data.js` (see `POLES_INTEGRATION.md` /
  the `pricing-data.js` header). The Jetti card on pricing.html is NOT Sheet-driven.
- **The phone knowledge base** `goodcall-knowledge.html` → generated by
  `tools/gen_knowledge_base.py`.

---

## How to tell if something is Sheet-driven

Open the page's HTML and look at the element. It's Sheet-driven if it has any of:

| Attribute / pattern | What the Sheet controls |
|---|---|
| `data-cms-text="some_key"` | the element's **text** |
| `data-cms-href="some_key"` | the link's **URL** |
| `data-cms-src="some_key"` | the image's **source** |
| `data-cms-target="some_key"` | whether the link opens a **new tab** |
| `data-cms-display-if="some_key"` | whether the element **shows at all** |
| a `DEFAULT_PRICING` / `DEFAULT_TIERS` / `VIBE_DEFAULTS` (etc.) JS constant | a **whole list** (pricing rows, vibe cards…) — the matching Sheet tab overrides it |

If an element has none of those, it's plain static content and you edit it in the
repo like normal.

**Where the key lives:** a `data-cms-*` key is looked up first in the **Pages** tab
(the row whose `slug` = this page), then in **SiteConfig** / **Photos**. A value in
either wins over the repo. Page-specific copy → **Pages**; site-wide copy (footer,
social, contact) → **SiteConfig**; photos → **Photos**.

---

## Force the site to show your Sheet edit now

The site caches CMS data for **60 seconds** in two places (the browser and the
Apps Script server). After editing the Sheet, either wait a minute, or add
**`?refresh=1`** to the page URL to bypass both caches immediately, e.g.:

```
https://www.cruisethecreek.com/pricing.html?refresh=1
```

## The spots that have bitten us (edit the Sheet, not the repo)

These are the exact places where a repo edit silently does nothing on production
because a Sheet value overrides it.

| What | Repo file (fallback) | To change it on production, edit… |
|---|---|---|
| Homepage **Book Now** button URL | index.html (`href` + `data-cms-href="cta_btn_primary_url"`) | **SiteConfig** → `cta_btn_primary_url` (and `cta_btn_primary_external` = FALSE for same-tab) |
| Homepage **Book a Test Ride** URL | index.html (`cta_btn_secondary_url`) | **SiteConfig** → `cta_btn_secondary_url` |
| Homepage hero CTA | index.html (`hero_cta_url` / `hero_cta_label`) | **SiteConfig** → `hero_cta_url`, `hero_cta_label` |
| Rentals **Book Trailside** (Kirk) button | rentals.html `VIBE_DEFAULTS.kirk.book_url` | **RentalsVibe** → Kirk row `book_url` (set to `choose-your-journey.html`, or clear it to use the repo default) |
| E-bike prices ($25/$35/$45/$55, rate note) | pricing.html `DEFAULT_PRICING` / `DEFAULT_TIERS` | **Pricing** and **PricingTiers** tabs |
| Any hero photo | e.g. index.html `data-cms-src="hero_photo"` | **Photos** (or SiteConfig) → `hero_photo` |
| Footer tagline / copyright | every page `data-cms-text="footer_tagline"` | **SiteConfig** → `footer_tagline`, `footer_copyright` |
| Social icons (show/hide) | index.html `data-cms-display-if` | **SiteConfig** → `social_instagram` / `social_facebook` / `social_tiktok` / `social_youtube` |

> Rule of thumb: if you edited an HTML file and the change didn't appear after a
> hard refresh + `?refresh=1`, the value is coming from the Sheet. Find its
> `data-cms-*` key in the HTML and edit that key in **Pages** or **SiteConfig**.

## Under the hood (for developers)

- **Loader:** `cmsBoot({key, url, onApply})` lives in `cms-loader.js` **and** is
  duplicated inside `site-enhance.js` (because `cruisethecreek.com` returned 500
  for `/cms-loader.js` — a route conflict with the old Wix `/cms` path). Pages get
  `cmsBoot` from whichever loads.
- **Flow:** the loader paints from the localStorage cache instantly, then fetches
  fresh JSON (unless the 60s TTL is still fresh and `?refresh=1` isn't set), and
  re-renders only if the payload changed. There is **no fallback logic in the
  loader** — each page renders its baked-in defaults first, and they simply never
  get overwritten if the fetch fails.
- **Applying values:** each page has its own `applyCMS(remote)` that walks
  `data-cms-*` elements. `pageMeta` (Pages tab) is merged **over** `site`
  (SiteConfig + Photos), so a key present in Pages wins over SiteConfig.
- **Backend:** `apps-script.gs` `doGet` returns one big JSON object with **every**
  content tab on **every** request; `?page=` only changes `pageMeta`, `sections`,
  `galleries`, and which `{Cap}_Tiles`/`{Cap}_Submenus` are returned.
- **Server cache:** each tab is cached 60s in Apps Script (`CacheService`), busted
  by an `onEdit` trigger and bypassed by `?refresh=1`.
- **Three Apps Script deployments are in use** (tech debt — a single deployment
  would mean fewer stale-URL breakages):
  1. **Primary** (`AKfycbwXv6r6…`) — all `?page=` CMS reads + most form POSTs.
  2. **Secondary** (`AKfycbyxVMuF…`) — inventory / storefront (`INV_URL`).
  3. **Admin** (`AKfycbxmzlQL…`) — invoice / balance / image-migration tools.
